# MFA implementation — approved B2 scope

The market-readiness plan authorizes mandatory MFA for staff; implementation
approach confirmed with the coordinating task before central changes.

## Design

Use Supabase TOTP, validated Auth users, and the JWT that PostgREST verifies.
One private database policy has an initially false application-ready switch and a nullable staff enforcement timestamp: migration
installation alone does not lock existing accounts out. Verified factor enrollment
records persistent account protection; removing factors cannot silently disable it.
Staff means a current accepted membership in a live organization, regardless of
the currently selected organization or whether the same account has a patient role.
Patient-only accounts without enrollment remain under first-factor authentication.

For protected accounts, authorization requires AAL2, a still-existing session for
the user, and a currently verified factor. Database checks query live state; neither
client metadata nor a decoded-but-unverified JWT establishes permission.
Restrictive RLS covers the public tables and Storage. An explicit inventory of
exposed SECURITY DEFINER helpers gets a guard while preserving function OIDs,
signatures/defaults, grants, volatility, and dependencies (no bulk renaming).

Server session helpers guard both staff and portal paths before privileged work.
Middleware adds navigation/JSON handling; it is not the sole enforcement layer.
Enrollment, challenge, password recovery, signout and a manual recovery explanation
remain reachable. A password-reset email alone never resets MFA. Existing factors
must be challenged before enrolling another device. New TOTP secrets are displayed
only during enrollment and are never logged or persisted in browser storage.

## Deployment contract

Apply additive M101 before dependent code. Deploy reachable MFA UI, then enable the audited preparation switch. Enroll and
rehearse recovery with staff while global enforcement remains NULL. Test actual
Supabase Auth/JWT/Storage and session refresh. Only then set the staff enforcement
timestamp under a privileged, audited maintenance procedure before any real pilot.
Never use an email-only, organization-switching or portal route exception to bypass
the activated policy. Background service jobs have no human actor and keep their
existing independent credentials; user-initiated service operations must validate
the requesting user's session first.
