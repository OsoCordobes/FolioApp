Cerrar paquetes técnicos no equivale a estar listo para recibir pacientes reales.

## Forma de trabajo más eficiente

- Dos escritores como máximo: uno en operación/fiabilidad y otro en experiencia/comercial. Un revisor se activa cuando existe una entrega concreta; los demás quedan inactivos, sin fabricar tareas.
- Encargos pequeños con base, archivos, resultado, prueba necesaria y condición de cierre. Preferir completar/publicar lo construido a abrir funciones nuevas.
- Una revisión proporcional al riesgo. No repetir una prueba aprobada sin cambio relevante, fallo o duda concreta. Ante fallo, investigar antes de reintentar.
- Sol 6.1 High para implementación y revisión relevante; Medium para operaciones acotadas. Ultra para una dificultad concreta o dirección visual, no como ajuste automático de todos los agentes.
- El manager asigna, resuelve dependencias y acepta resultados. No vuelve a desarrollar ni audita por completo lo que ya revisó otro: contrasta identidad, evidencia y límites.
- Cada entrega registra sólo qué cambió, cómo se comprobó, dónde probarlo y qué falta. Preparar herramientas, informes o propuestas no cuenta como función terminada.
- Una propuesta visual rechazada se conserva como antecedente y no se cuenta como mejora. No se añade otro rediseño o pruebas repetidas para justificar el tiempo ya invertido.
